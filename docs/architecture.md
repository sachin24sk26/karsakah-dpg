# KARSAKAH &rarr; Architecture & Technical Design

## 1. System Overview

KARSAKAH is an open-source **Digital Public Good (DPG)** designed for smallholder farmers across BRICS+ countries. It combines **explainable agronomic rules**, **multilingual voice interfaces**, **open geospatial data connectors**, and **simulated federated intelligence** to deliver actionable regenerative farming guidance.

```
Farmer (Web App / Voice / WhatsApp Mock)
        │
        ▼
 KARSAKAH Front-End (Responsive, Multilingual, Low-Bandwidth)
        │  REST (OpenAPI 3.0 Contract)
        ▼
 Advisory API Gateway (/v1/data, /v1/advisory, /v1/diagnose, /v1/node/info)
   ├── Data Connectors: Open-Meteo · SoilGrids (ISRIC) · Sentinel-2 STAC · NASA POWER
   ├── Regenerative Rules Engine (Suitability, Crop Rotation, Moisture, Nitrogen Fixation)
   ├── Disease Vision Engine (Gemini Multi-Modal + Structured Output Schema + Confidence Gate)
   └── Country Profile Loader (/country_profiles/{ISO}.json)
        │
        ▼
 Federated Node Registry (Interoperable Architecture)
   🇮🇳 India Node (Punjab / ICAR) · 🇧🇷 Brazil Node (Cerrado / Embrapa) · 🇿🇦 South Africa Node (KZN / ARC)
```

## 2. Core Architectural Principles

1. **Config-Driven Multi-Country Architecture**:
   - One unified codebase.
   - Regional characteristics (crops, languages, currency, agro-climatic seasons, extension contacts) are defined in `/country_profiles/{ISO}.json`.

2. **Explainable Agronomic Engine**:
   - Recommendations are generated by transparent, verifiable rule modules based on FAO EcoCrop and regional agricultural institutes (ICAR / Embrapa).
   - Every recommendation provides **explicit reasons** (`why`), **regenerative practices**, and **data freshness metadata**.

3. **Data Quality & Confidence Scoring**:
   - Confidence is computed from data availability and freshness (e.g. live weather forecast + 250m soil grid vs. regional defaults).
   - When confidence is below threshold (<0.6), the platform prompts for local extension officer consultation instead of guessing.

4. **Sovereign Data Boundary & Indicator Exchange (Federated Node Architecture)**:
   - Identifiable farmer records, farm imagery, and plot-level coordinates remain strictly domestic within each sovereign national node.
   - Cross-border federation exchanges exclusively **anonymized macro-indicators, regional pathogen risk alerts, and standardized Model Cards** (not distributed weight training or centralized data pooling).

## 3. Standard API Endpoints

- `GET /v1/data?lat={lat}&lon={lon}&country={country}`: Returns normalized weather, soil, and vegetation bundle with data freshness metadata.
- `POST /v1/advisory`: Generates prioritized crop recommendations, rotation plans, and regenerative practices.
- `POST /v1/diagnose`: Multi-modal leaf diagnosis returning structured JSON with organic-first controls and confidence score.
- `GET /v1/node/info?country={country}`: Returns node metadata, model cards, and shared federated insight alerts.
